Go · 进程外插件 Runtime · Frame v2

Host 只做平台，
业务全在插件里。

LiteAgent 是一套轻量、可组合的进程外插件 Runtime。Host 提供插件发现、进程管理、 Capability 路由和 WebUI 平台壳；具体业务由独立插件提供。两个层次互不越界。

    分层职责

    六个平台模块，加上一个不属于内核的扩展层。点任意模块看它的职责与非职责。

    02

    Frame 线契约

    Host 与插件通过 stdio 交换 Frame：4 字节大端长度加 UTF-8 JSON body，单条上限 16 MiB。改下面任一字段，看线格式怎么变。

    Host 只理解这些平台字段

    payload 对 Host 不透明。插件方法 payload、Fact、View State 和业务错误由插件文档定义。

    全部稳定 error_code protocol/errors.go · 30 个

    03

    两层路由与流水线

    路由键只有 (capability, method)。同一把键上可以有 Provider 和多个 Consumer，Host 按 priority 把它们串成消费链。

    路由

    capability.method → Plugin
    context_id → Plugin Instance
    • 插件名不参与路由，只用于 from、日志、id 前缀和依赖图。
    • 无 context_id 的调用进入默认实例；执行上下文绑定决定 Capability 落到哪个实例及其固定 Generation。
    • host.register 是路由表唯一写入口，跨插件同键冲突进入 rejected。

    Frame Priority 流水线 · llm.complete

    Consumer Route Owner priority 越大越先进入流水线

    Consumer 不抢占 Owner，但缺席就放行。已声明为 Consumer 的插件只进链，不夺走 Provider 的路由键； 而当某个 Consumer 当前不活跃时，Host 跳过这一跳，把调用交给 Provider——这是部署约定，不是平台保证的强制拦截。

    04

    插件图谱与降级

    九个插件构成当前发布集，其中六个是可选件。关掉 model-context、tools、sandbox 或 subagent，看链路怎么降级——这是可组合性的实际含义。

    depends_on（硬依赖，决定启动顺序） requires（弱依赖能力） 消费链接缝 Proceed 实线由依赖方指向被依赖插件

    接缝全景 同一把路由键上的成员按 priority 递减排列

    成员资格由 manifest 的 consumes 与运行时注册的同名 handler 共同决定；priority 只决定链内顺序。Consumer 缺席时这一跳被跳过。

    05

    一次 Turn 的完整链路

    从浏览器点击发送到 UI 推送收口。跟着播放看每一跳，或切到工具轮、沙箱裁决与确认、子代理委派、取消、异常、刷新场景。静态总览图见 数据流转 · 完整数据流转。

    06

    WebUI 平台壳

    Host 提供 Shell、五 Slot、Loader 和 Browser Bridge；Component 由插件拥有。同一 Slot 可以容纳多个 Mount，实例身份是插件名加 mount_id。Plugin Runtime 只驱动自己拥有的 Component。

    State 与 Command

    
        
    State 应可由 Plugin Runtime 重建；Command 可以是临时行为。刷新后不重放事件。
