## 5. 详细复现

以下记录保留初测现象，用于复现和回归。I-01、I-02、I-03 的修复结果见第 11 节。

### 5.1 I-01 刷新后选中会话丢失

步骤：

1. 在会话列表中选择任意历史会话。
2. 确认聊天区和 Facts 面板已加载。
3. 刷新页面。

实际：会话列表仍在，主区显示“新会话”和空 Facts。
预期：刷新后恢复上次选中的会话，PRESSURE U2 和 S1 均要求该行为。
证据：刷新后 DOM 中 `.head-title` 为“新会话”，Facts 计数为 0；再次点击同一会话后内容正常。

代码线索：

- `plugins/session/ui/store.js:86` 的 `bootstrap()` 只加载工作区、模型和会话列表。
- 该函数没有读取上次选中的 `sessionId`，也没有写入任何持久化存储。
- `plugins/session/ui/store.js:171` 的 `selectSession()` 只修改内存状态。

### 5.2 I-02 失败回合刷新后消失

步骤：

1. 新建会话，选择 `gemma-4-e2b`，该模型端点不可用。
2. 发送“只回复 OK，不要调用任何工具”。
3. 等待错误出现，然后刷新页面并重新打开该会话。

实际：错误出现时聊天区可见；刷新后只剩用户消息，没有错误提示。
预期：失败回合可见，刷新后保留，并提供重试入口。
证据：会话 JSONL 第 6 条为 `turn_end`，`status=error`；聊天区只渲染 `message` 角色，不渲染 `turn_end`。
诊断面板能看到 `loop.turn handler_error`，普通用户必须先发现诊断入口。

代码线索：

- `plugins/session/ui/chat.js:275` 的 `appendMessage()` 只处理消息角色。
- `turn_end` 的 `status=error` 没有映射为聊天区错误块。
- 聊天区没有重试按钮，`store.js` 的失败分支只调用 `reportError("本轮", error)`。
- 第二次发送相同提示后，诊断计数从 1 合并为 2，说明诊断去重正常。

### 5.3 I-03 取消终态刷新后不可见

步骤：

1. 发送一个会执行 30 秒 shell 命令的任务。
2. 在工具执行阶段点击停止。
3. 观察终态，再刷新并重新打开会话。

实际：停止立即生效，子进程被终止，`turn_end` 为 `cancelled`。
聊天区显示“已停止 · 本轮内容未保存”，但助手消息已经写入 Facts。
刷新后“已停止”提示消失，聊天区看起来像正常完成。

预期：取消终态在刷新后仍可见，提示文案与落库事实一致。
代码线索：`plugins/session/ui/chat.js:318` 使用固定文案；刷新后只从消息事实恢复，`turn_end.cancelled` 不再参与渲染。

### 5.4 I-04 1 MiB 工具输出完整进入 DOM

步骤：

1. 要求 Agent 用 shell 执行 `python -c "import time; time.sleep(6); print('x'*2000000)"`。
2. 工具返回 `truncated=true`，内容长度为 1,048,576 字符。
3. 打开该会话，统计聊天 DOM。

实际：单个 `.msg.other` 节点长度为 1,048,583 字符。
页面没有截断标记、展开按钮或懒加载。
聊天区文本长度为 1,059,600，Trace 文本长度为 1,061,416。

预期：截断可见，默认折叠或懒加载，页面不因单条输出冻结。
代码线索：

- `plugins/session/ui/chat.js:289` 把 `tool` 结果整体放入文本节点。
- `plugins/session/ui/trace.js:36` 直接返回 `text_content`，没有按长度截断。
- 工具结果中的 `meta.truncated` 没有进入展示层。

### 5.5 I-05 重新扫描清空运行时诊断

步骤：

1. 触发一次 `loop.turn` 错误，诊断计数为 2。
2. 放入一个无效 `ui.entry` 探针，重新扫描，诊断计数变为 3。
3. 移除探针并重新扫描。

实际：计数回到 1，之前的 `loop.turn handler_error` 消失，只剩 sandbox 诊断。
预期：重新扫描只更新插件发现类诊断，运行时错误应继续保留。
代码线索：`internal/webui/management.go:33` 将 `s.diagnostics` 直接替换为 registry 诊断。
该赋值丢失了 `PushDiagnostic` 追加的运行时诊断。

### 5.6 I-06 sandbox 未激活时产生常驻诊断

步骤：

1. 启动 Host，不激活 sandbox。
2. 打开诊断面板。

实际：存在 `sandbox.pending.list` 的 `method_not_found`，计数为 5。
启动 sandbox 后，同一方法返回 `{"pending":[]}`，诊断不再新增。
预期：未激活插件的 UI 不应挂载，也不应调用未注册方法。

代码线索：`plugins/sandbox/ui/main.js:127` 调用 `pending.list`。
sandbox 的 `ui` 声明仍被 bootstrap 装载，插件状态未参与 UI 挂载决策。

### 5.7 I-07 长会话一次性渲染

步骤：

1. 创建 250 条消息、500 Facts 的 D2 会话。
2. 通过真实 bridge 追加 1 KiB、50 KiB、1 MiB 文本事实。
3. 在 UI 中首次打开并刷新。

实际：加载完成耗时约 1.03 秒（500 Facts），追加 1 MiB 后约 1.63 秒。
聊天区同时存在 250 个 `.msg` 节点，Trace 同时存在 525 个 `.fact` 节点。
Trace 文本量约 1.79 MB，没有分页或虚拟化。

预期：D2 可用，D4 仍应保持可交互；PRESSURE U5 要求按需加载更早消息。
代码线索：`plugins/session/ui/store.js:184` 一次加载全部消息和 Facts；`chat.js:223` 一次渲染全部消息。

### 5.8 I-08 运行期间元数据不更新

步骤：

1. 新建会话，发送一个会触发多次工具调用的任务。
2. 在生成期间观察标题、消息数和 Facts 面板。

实际：标题保持“新会话”，消息数为 0，Facts 为 0。
左侧列表已显示“5 条记录”，聊天区已显示用户消息和推理内容。
回合结束后才变为真实标题、17 条消息和 26 Facts。

预期：运行期间至少显示会话已建立、消息数和 Facts 的增量。
代码线索：`plugins/session/ui/store.js:435` 只在结果返回后设置 `turn.status = "done"` 并刷新会话。

### 5.9 I-09 日志无轮转且记录完整帧

测试期间 `server-20261103.log` 从 0 增长到 3,279,878 字节，约 30 分钟。
日志包含完整推理增量、工具结果和消息正文，没有时间戳，也没有轮转策略。
长会话或 1 MiB 工具输出会持续放大日志体积。
Host 重启后新建 `server-20261103-restart.log`，同样没有轮转。

### 5.10 I-10 推理内容无限渲染

W1 使用 `mimo-v2.6-flash` 时，模型在推理通道连续输出代码草稿。
前 8 分钟没有创建任何文件，页面推理节点从 18,472 字符涨到 55,520 字符。
整轮共保存 62,843 字符推理文本，回合耗时 12 分 03 秒。
运行期间页面始终显示“生成中”，没有推理折叠、最大长度或超时提示。
`plugins/llm-openai/plugin.go:27` 创建 `http.Client{}` 时没有超时。
`buildChatRequest` 也没有设置 `max_tokens`。上游持续输出时，回合只能等待。

### 5.11 I-11 错误提示重复且不可重试

失败回合同时出现顶部 toast 和聊天区内联错误。
两处文案都是原始 Go 传输错误，包含 `dial tcp [::1]:1145` 和 `connectex`。
聊天区只有“关闭”按钮，没有“重试”或“保留输入”。
用户需要重新输入提示，违反 PRESSURE U4 的“重试不丢草稿”。

### 5.12 I-12 dist 落后于源码

启动日志版本为 `08c5552-dirty`。
当前 HEAD 为 `5b4db09`，工作区还有大量未提交改动。
`dist` 不能代表当前源码。修复前需要先重新构建，否则容易把已修问题当成未修。

## 8. 修复建议

P0 第 1～4 项已完成，见第 11、12 节。
P1 第 1～3 项已完成，见第 12 节。
P1 第 4～6 项与 P2 建议保留。

P0：

1. 在 `localStorage` 或会话元数据中保存当前 `sessionId`，启动后恢复选中会话。
2. 将 `turn_end` 的 `error` 和 `cancelled` 映射为聊天区终态块。失败回合刷新后仍要可见。
3. 为失败回合增加重试按钮，并保留失败提示的草稿。
4. 工具输出在展示层按字节截断，默认折叠，展开时再加载全文。

P1：

1. 重新扫描时合并 discovery 诊断和运行时诊断，不能直接覆盖。
2. UI 挂载前检查插件实例状态。未激活插件不加载 UI，或让 UI 等待能力可用。
3. 聊天区按窗口渲染，Trace 按需加载 Facts。至少为 1000 Facts 以上的会话增加分页或虚拟列表。
4. 运行期间增量更新标题、消息数和 Facts 计数。
5. 给 Host 日志增加时间戳、级别、帧摘要和轮转，避免记录完整大帧。
6. 给 LLM 流设置请求超时和最大输出量。超时后写入失败终态，并允许用户重试。

P2：

1. 统一错误文案，隐藏传输层细节，保留稳定错误码。
