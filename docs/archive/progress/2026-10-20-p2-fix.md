## 2. 取消提示

### 2.1 实现

Agent 在写入 `turn_end(cancelled)` 的同一批次追加一条提示 Fact：

```json
{
  "type": "message",
  "role": "user",
  "content": "The user cancelled the previous turn before it completed. Do not continue that task unless the user explicitly asks again.",
  "meta": {
    "kind": "turn_cancelled",
    "turn_id": "t-..."
  }
}
```

特点：

- 写入 Session Fact Log，模型可见且可审计。
- 与 `turn_end` 同批写入，减少只写一半的状态。
- `session-chat` 不渲染为聊天气泡。
- `session-trace` 仍能看到该 Fact。
- 取消轮的状态行继续显示“已取消”。

### 2.2 验证

真实取消后，Session JSONL 包含：

- `turn_end(reason=cancelled)`。
- `kind=turn_cancelled` 的用户消息。

`session.derive` 的输出包含该提示，位置在取消的用户消息之后。
聊天区没有出现提示气泡。
状态行显示“第 1 轮 · 已取消”。

新增测试：

- `TestPreCancelledTurnWritesTerminal` 检查提示与 `turn_end` 一起写入。
- `TestCancelledTurnNoteStaysOutOfChat` 检查 ChatState 与 chat append 都过滤该消息。

## 3. 慢连接恢复

### 3.1 旧行为

队列满时只给该连接丢帧。
页面可能停在旧状态。
尾部丢帧没有后续帧时，客户端无法靠游标断点发现。

### 3.2 新行为

队列满时：

1. 该连接记录一次 drop。
2. 标记 overflow。
3. 设置写截止时间，唤醒已阻塞的写。
4. 关闭该连接。
5. SDK 重连后收到 hello，触发 resync。
6. 其他连接不受影响。

实现位置：

- `internal/webui/publisher.go`。
- `uiConnection.markOverflow`。
- `serveUI` 的 overflow 分支。

### 3.3 验证

Go 测试：

- `TestServerUISaturatedQueueDropsOnlyThatConnection` 检查 overflow 被标记且写端被唤醒。
- 快速连接仍收到新 State。

浏览器外集成：

- 两个 `/bridge/ui` 连接。
- 一个持续读取，一个暂停。
- 追加 100 条 4 KiB 消息。
- 慢连接被关闭，读取返回 terminated。
- 快连接保持打开，并继续收到后续 3 帧。
- 服务端记录 `ui: queue full ... closing=true`。

## 4. file-tools 错误文案

### 4.1 实现

`file_write` 现在：

- 对目标路径无条件 `Stat`。
- 目录目标返回 `path_is_directory`，消息包含路径。
- 写入失败消息包含动作与路径。
- 缺少父目录时消息包含目标路径。

### 4.2 测试

新增：

- `TestWriteRejectsDirectoryPath`。
- `TestWriteMissingParentNamesPath`。

错误码保持稳定，只改进消息。

## 5. 旧错误清理

session 组件的 `resync()` 与 `refresh()` 成功后会清空错误提示。
这样插件重启或页面重连后，不会保留旧的 `network error`。

## 7. 剩余风险

### 7.1 Host writer goroutine

Host 读循环仍可能同步写回调用方。
插件持续消费 stdin 后可以恢复。
第三方插件不读 stdin 时仍可能拖住自己的读循环。

### 7.2 取消提示的模型效果

提示能降低误续写概率。
模型仍可能忽略提示。
该 Fact 会增加少量上下文 Token。

### 7.3 大 State 预算

D2 State 仍可达到 5 MB 以上。
窗口常量与状态裁剪仍是独立任务。

### 7.4 W1 提前收尾

这是模型行为，不是平台终止。
没有在平台层加入文本启发式。
