# 落地计划

> 状态：目标契约
> 说明：本文是落地计划。阶段一到阶段六都还没实现，当前实现在第 0 节列了差距。
> 配套：[12-assets.md](12-assets.md) 给出可直接使用的文本，[13-application.md](13-application.md) 给出 session/model-context 的应用方法与三条落地路径。

本文把 [01-principles.md](01-principles.md) 到 [08-invariants.md](08-invariants.md) 的内容拆成可交付的阶段。

每个阶段给出目标、落点、验收标准和明确不做的事。

## 0. 现状盘点

当前实现的基线已经不算差。以下是差距清单。

| 项 | 当前实现 | 目标契约 | 差距 |
|---|---|---|---|
| 分节 | 有 `prompt_sections`，带 `name`、`order`、`text` | 增加 `track` | 轨道归属靠约定 |
| 轨道边界 | system prompt 与运行时上下文是两条消息 | 显式轨道字段 | 隐含 |
| 变量 | 四个变量，未知变量报错 | 静态与动态变量分治 | 静态轨可混入动态变量 |
| 工具描述 | 只有 `description` 与 schema | 三件套 | 跨调用纪律无处安放 |
| 工具纪律 | 静态轨里是手写固定文本 | 由工具注册表贡献 | 卸载工具后条目仍在 |
| 工具默认值 | schema 写了上限，没写默认值 | 默认值与上限都写进参数描述 | 模型按上限预期，撞上实际默认值 |
| 注入标签 | 运行时上下文是裸文本 | `<runtime_context>` 信封 | 模型无法区分框架事实 |
| 转义 | 无 | 保留标签转义 | 外部内容可伪造标签 |
| 压缩 | 确定性摘要 | 模型摘要加确定性兜底 | 摘要丢意图 |
| 截断 | 只有 `truncated` 布尔 | 原始长度、砍掉长度、落盘路径 | 模型不知道丢了多少 |
| 运行时上下文 | `## Mode` 与 `## Scheme` 内容相同 | 两者承载不同信息 | 同一份事实渲染两遍 |
| 子代理 | 未实现 | 画像三段式 | 缺 |

盘点结论：阶段 1 到阶段 3 是必须先做的。它们是后面所有能力的地基。

阶段 1 之前有一件不用改代码的事：把静态轨八节写进 `plugins/model-context/config.json`。见 [12-assets.md](12-assets.md) 第 3 节。这件事的效果比阶段 1 到阶段 3 加起来更直接。

上表里"工具默认值""截断""运行时上下文"三项的完整分析见 [13-application.md](13-application.md) 第 8 节。

## 1. 阶段一：轨道拆分

**目标。** 让缓存边界成为显式契约。

**落点。** 上下文装配插件的配置与渲染层。

| 改动 | 说明 |
|---|---|
| 配置增加 `track` 字段 | 缺省时按 `order < 0` 推断 |
| 渲染按轨道拆分 | 静态轨进系统提示记录，动态轨进运行时上下文记录 |
| 静态性守卫 | 静态轨出现动态变量时渲染失败 |
| 分节词表落地 | 十二个标准节名，顺序键固定 |

**验收。**

- 连续 10 轮渲染，静态轨哈希不变。
- 工作区变化时静态轨哈希不变，动态轨哈希变化。
- 静态轨出现 `{{workspace}}` 时渲染失败，错误码 `prompt_variable_not_allowed`。

**不做。** 不改工具契约。不改注入信封。

## 2. 阶段二：工具三件套

**目标。** 让跨调用纪律由工具提供方贡献，并随工具在场性出现与消失。

**落点。** 工具注册表插件的注册契约，上下文装配插件的渲染层。

| 改动 | 说明 |
|---|---|
| 工具定义增加 `guidelines` | 字符串数组，可选 |
| 工具定义增加 `prompt_snippet` | 字符串，可选 |
| 纪律节改为动态渲染 | 按在册工具拼接 |
| 描述校验 | 描述五段结构检查 |
| 工具结果增加截断元数据 | `original_bytes`、`truncated_bytes`、`artifact_path` |

**验收。**

- 卸载一个工具后重新渲染，纪律节不含该工具的条目。
- 工具描述里的超时数值随配置变化。
- 描述与纪律节之间无同一事实的两次表述。
- 产生截断的工具结果带 `original_bytes` 与 `truncated_bytes`。

**不做。** 不做工具暴露面三态。不做工具检索。

**阶段二之前。** 工具描述改写不需要改结构，只改文本。9 个工具的描述与参数默认值见 [12-assets.md](12-assets.md) 第 4 节。改完就生效，不必等阶段二。

其中 `shell_execute` 的描述最要紧：现有描述用否定式说明"管道不解释"，模型仍会写 `| head`。改写后是正面表述加替代动作。

截断元数据是阶段二里唯一有新增行为的一项。`file_read` 容易，它已经有 `meta.size` 与 `meta.line_count`。`shell_execute` 难——超出部分要落盘才能给 `artifact_path`，这是新的落盘行为。分析见 [13-application.md](13-application.md) 第 8.3 节。

## 3. 阶段三：注入信封与转义

**目标。** 让模型能可靠区分框架事实与外部内容。

**落点。** 上下文装配插件的渲染层。

| 改动 | 说明 |
|---|---|
| 运行时上下文加 `<runtime_context>` 包裹 | 单一渲染函数产出 |
| 保留标签转义 | 用户可控文本中的保留标签转义 |
| 用户指令文件分层 | 目录作用域与优先级链 |
| 外部内容声明 | 返回外部内容的工具描述固定一句 |

**验收。**

- 用户输入含 `</system-reminder>` 时，落盘正文为 `&lt;/system-reminder>`。
- 运行时上下文含优先级声明。
- 清空快照存在，上下文从有到无时产生一条。

**不做。** 不做后台任务通知前缀。子代理插件落地后再做。

## 4. 阶段四：压缩模型摘要

**目标。** 摘要保留意图与待办。

**落点。** 上下文装配插件的压缩路径。

| 改动 | 说明 |
|---|---|
| 模型摘要路径 | 一次辅助调用，固定九节骨架 |
| 落库前校验 | 九节齐全、意图逐字、无思考段、无工具调用 |
| 失败退回 | 退回确定性摘要 |
| 恢复消息 | 压缩后插入续作说明 |
| 保密令 | 摘要里不提及本次压缩请求 |

**验收。**

- 四类坏摘要输入都不落库，旧摘要保留。
- 二次压缩后摘要不含已失效事实。
- 摘要边界不落在工具调用与结果之间。

**不做。** 不做轮次中途压缩。不做多级检查点。

## 5. 阶段五：子代理画像

**目标。** 子代理有自己的纪律与输出契约。

**落点。** 子代理插件，以及委派工具的描述。

| 改动 | 说明 |
|---|---|
| 画像三段式 | 身份、禁令、输出契约 |
| 委派元指令 | 写进委派工具描述 |
| 权限冻结声明 | 画像固定追加 |
| 深度双检 | 委派侧与执行侧都检查 |

**验收。**

- 画像含三段，禁令逐条列举。
- 子代理提示自足，不依赖父会话。
- 委派侧与执行侧的深度检查都生效。

**不做。** 不做后台子代理。不做孙代理。

## 6. 阶段六：防退化测试

**目标。** 把不变量固化成测试。

**落点。** 上下文装配插件的测试文件。

| 测试 | 对应不变量 |
|---|---|
| 静态轨哈希稳定 | I1 |
| 变量守卫 | I2、I3 |
| 节名唯一 | I4 |
| 工具在场性 | I6、I7 |
| 大写词限量 | I8 |
| 标签唯一产出 | I9 |
| 转义 | I10 |
| 摘要校验 | I11 |
| 调试同源 | I12 |
| 体积预算 | I13 |
| 配对不切开 | I14 |
| 注入预算 | I15 |

**验收。** 全部测试通过。故意破坏任一不变量时，对应测试失败。

## 7. 阶段间依赖

```text
阶段一（轨道拆分）
  ├── 阶段二（工具三件套）
  └── 阶段三（注入信封）
        └── 阶段四（压缩模型摘要）

阶段一 + 阶段五（子代理画像）
        └── 阶段六（防退化测试）
```

阶段一必须先做。阶段二与阶段三互不依赖，可以并行。

阶段四依赖阶段一。阶段五依赖子代理插件先落地。

阶段六在每阶段结束时补齐对应测试，不必等到最后。

## 8. 取舍记录

| 取舍 | 理由 |
|---|---|
| 模型侧 prompt 用英文 | 训练数据与指令遵循的偏置在英文侧 |
| 静态轨不做字数压缩 | 压缩会让缓存前缀变化，抵消缓存收益 |
| 工具描述与纪律节分开 | 一个事实只出现一次 |
| 确定性摘要保留为兜底 | 压缩必须总能成功 |
| 不做工具暴露面三态 | v1 工具数量可控 |
| 不做多级检查点 | 复杂度收益不匹配 |
| 注入标签只留两个 | 标签越多，模型越难判断 |
