# 拼装与缓存

> 状态：目标契约

拼装决定最终请求长什么样。缓存决定这次请求要不要重新付全价。

## 1. 拼装架构

```text
┌─ 静态轨（system 消息，字节稳定，可命中前缀缓存）───────────┐
│ identity → persona → system_semantics → task_policy        │
│ → tool_discipline → communication → output_format → safety │
├─── ◀ 缓存边界：此后一切每轮可变 ──────────────────────────┤
│ environment → workspace_rules → skills → memory            │
│                                                          │
│ 摘要消息（激活时）                                        │
├──────────────────────────────────────────────────────────┤
│ 对话层：历史消息 + 尾部提醒片段                            │
│ 本轮输入                                                  │
└──────────────────────────────────────────────────────────┘
```

工具表与静态轨同源产出。工具描述由注册表贡献，按在场性条件渲染。

机制选型，从轻到重：

| 级别 | 做法 | 适用 |
|---|---|---|
| 轻 | 数组加边界哨兵 | 单插件部署 |
| 中 | 节注册表加增量 diff | 多插件共用一套 harness |
| 重 | 插件化注册表加顺序带 | 多团队共用 |

本项目当前是轻级。`prompt_sections` 就是数组加排序键。

- 出处：claude-code-main `src/constants/prompts.ts:114`；pi `coding-agent/src/core/system-prompt.ts:204-216`；deepseek-harness-x `packages/core/system-prompt/src/index.ts:56-60`

## 2. 缓存边界

四条共识。

**静态前缀字节稳定。** 永不变的内容放最前，合并成可命中提示缓存的单块。

**易变内容后置。** 环境、用户指令、技能、记忆、提醒全在边界之后。会话级变动混进静态前缀，会让缓存前缀的变体数按会话数增长。

**动态段分档。** 三档：

| 档 | 重算时机 | 用途 |
|---|---|---|
| 常驻 | 配置变化时 | 静态轨 |
| 记忆 | 显式清理或压缩时 | 摘要 |
| 变动 | 每轮 | 动态轨、提醒片段 |

**工具目录跨模式保持不变。** 用策略段落覆盖行为，不增删工具。请求形状稳定，缓存才能命中。

- 出处：claude-code-main `src/constants/prompts.ts:105-113`；ZCode `builder.ts:230-277`；deepseek-harness `packages/bundle/base/cordis.patch.yml:328-330`

## 3. 装配顺序

装配按固定顺序执行，任何一步失败都有明确的降级。

```text
1. 渲染静态轨
2. 渲染动态轨
3. 追加用户指令文件
4. 追加技能索引
5. 追加记忆条目
6. 投影会话历史
7. 插入摘要
8. 插入尾部提醒
9. 计算用量估算
10. 超预算则压缩后重来
```

降级规则：

| 情形 | 效果 |
|---|---|
| 某动态节无内容 | 跳过该节，不留空标题 |
| 某动态节来源不可用 | 跳过该节，记一条告警 |
| 用户指令文件读不到 | 跳过，记一条告警 |
| 动态轨整体为空 | 发一条清空快照 |
| 静态轨渲染失败 | 本次请求失败，不调用模型 |

静态轨渲染失败就失败，不能用空 prompt 继续。空 prompt 会让模型按训练分布自由发挥。

## 4. 摘要与历史的相对位置

摘要作为 system 消息插在系统提示之后。

动态轨在摘要之后。

这个顺序不能变。摘要要在历史之前，让模型先知道"这是接续的会话"，再读新事实。

- 出处：claude-code-main `src/services/compact/prompt.ts:311-335`；上下文组装插件的当前投影规则，见 [docs/design/plugins/04-model-context.md](../design/plugins/04-model-context.md)

## 5. 工具表与静态轨的一致性

工具表里的每个工具，都必须在静态轨里有对应的纪律条目，反之亦然。

| 情形 | 处理 |
|---|---|
| 工具有描述、无纪律 | 允许。描述承担全部语义 |
| 工具有纪律、无描述 | 不允许。工具没有描述，模型选不出来 |
| 两者都有且内容重复 | 不允许。删掉纪律里重复的部分 |

一致性由装配层检查。检查失败时记一条告警，不阻断请求。

## 6. 装配的可见性

调试时看到的装配结果必须等于模型收到的结果。

两者走同一条渲染函数。禁止"调试路径另写一套简化版"。

装配结果要能逐项核对：

| 项 | 核对内容 |
|---|---|
| 静态轨 | 分节列表与每节哈希 |
| 动态轨 | 分节列表与每节哈希 |
| 工具表 | 工具名列表与整体哈希 |
| 消息 | 顺序、来源标记、截断标记 |
| 用量 | 估算值与各部分占比 |

- 出处：pi `coding-agent/src/core/system-prompt.ts:195-197`；rea `src/server/catalogIdentity.ts:83-98`

## 7. 一切注入可重建

模型看到的一切都能从记录里重建。

这是本项目已有的强约束。系统提示、运行时上下文、摘要、工具表都有快照记录，可以按记录还原出当时的请求。

注入不落记录就等于不可观测。不可观测的注入无法排查。

- 出处：deepseek-harness-x `docs/architecture.md:96`

## 8. 验收标准

| 项 | 检查方式 |
|---|---|
| 前缀稳定 | 连续 10 轮静态轨哈希不变 |
| 边界有效 | 工作区变化时静态轨哈希不变，动态轨哈希变化 |
| 形状稳定 | 同一部署的请求形状不随轮次变化 |
| 降级明确 | 每个装配步骤都有明确的失败降级行为 |
| 空轨拒绝 | 静态轨为空时请求失败 |
| 一致 | 工具表与纪律节双向核对通过 |
| 同源 | 调试装配结果与模型收到的请求逐字节相同 |
| 可重建 | 按快照还原出的消息哈希与记录一致 |
