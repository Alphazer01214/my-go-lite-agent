# 不变量与测试

> 状态：目标契约

Prompt 质量的退化是渐进的。每次小改动都正确，合起来就不对了。

防线是自动化检查。检查写在测试里，和代码一起改。

## 1. 不变量清单

| 编号 | 不变量 | 检查方式 |
|---|---|---|
| I1 | 静态轨在同部署下字节稳定 | 连续渲染比较哈希 |
| I2 | 静态轨不含动态变量 | 渲染期拒绝，错误码 `prompt_variable_not_allowed` |
| I3 | 未知变量导致渲染失败 | 渲染期拒绝，错误码 `prompt_variable_unknown` |
| I4 | 节名唯一 | 渲染期拒绝，错误码 `prompt_section_duplicate` |
| I5 | 静态轨非空 | 渲染期拒绝 |
| I6 | 工具表与纪律节双向一致 | 装配期核对，记告警 |
| I7 | 工具名不写死在 prompt 文本里 | 文本检索 |
| I8 | 大写情态词限量 | 静态轨全文只允许 `NOT`、`ONLY`、`EXACT` |
| I9 | 保留标签只在渲染层产出 | 源码检索 |
| I10 | 用户可控文本已转义保留标签 | 渲染期转换 + 断言 |
| I11 | 压缩摘要含全部九节 | 落库前校验 |
| I12 | 调试装配结果与模型请求同源 | 同一渲染函数，断言逐字节相同 |
| I13 | 静态轨体积在预算内 | 字节上限断言 |
| I14 | 摘要不切开工具调用配对 | 边界位置断言 |
| I15 | 注入量在预算内 | 技能与记忆注入量断言 |

## 2. 变量守卫

变量插值必须 fail-loud。

裸插值不报错是隐蔽的失败模式。拼写错误的变量名静默替换成空串，prompt 少了一句话，没有任何地方报错。

```go
value, ok := vars[name]
if !ok {
    return "", errBadArguments("unknown prompt variable: {{" + name + "}}")
}
```

这条规则已经是当前实现的行为。本文把它固定为不变量。

- 出处：deepseek-harness `packages/core/system-prompt/src/index.ts:336-357`

## 3. 静态性守卫

比未知变量更隐蔽的错误是"静态轨里放了一个合法但会变的变量"。

```go
if track == TrackStatic && isDynamicVariable(name) {
    return "", errBadArguments("dynamic variable in static track: {{" + name + "}}")
}
```

渲染期拒绝比事后检查可靠。事后检查容易漏掉边缘路径。

## 4. 体积预算

| 预算 | 上限 | 理由 |
|---|---|---|
| 静态轨单节 | 4 KiB | 一节不该长到需要滚动 |
| 静态轨全文 | 16 KiB | 软上限，超出记告警 |
| 动态轨全文 | 32 KiB | 含用户指令文件与记忆 |
| 单条工具描述 | 2 KiB | 工具描述注册时已限制在 8 KiB，渲染层再收窄 |

- 出处：grok-build `templates/` 渲染器的体积检查，见 `grok-build/analysis/prompt-writing.md`

## 5. 工具在场性

工具不在场时，对应的段落自动消失。

断言方式是渲染两次：一次带该工具，一次不带。带的时候条目存在，不带的时候条目不存在，且文本长度变短。

这比断言"文本包含某字符串"更严，能发现"该消失的段落还在"这类问题。

- 出处：deepseek-harness `packages/fs/tool-fs/src/read.ts:70-75`；pi `coding-agent/src/core/system-prompt.ts:101-109`

## 6. 调试同源

调试时打印的装配结果必须等于模型收到的请求。

做法是复用同一个渲染函数。禁止维护第二套简化渲染。

- 出处：pi `coding-agent/src/core/system-prompt.ts:195-197`

## 7. 工具描述与纪律节的一致性

两条检查。

**一，描述里的数值来自配置。** 断言描述文本随配置变化。改配置后描述没变，说明数值被写死了。

**二，纪律条目随工具在场性变化。** 断言卸载工具后条目消失。

## 8. 摘要校验

落库前逐项校验：

| 项 | 校验 |
|---|---|
| 九节齐全 | 节标题全部出现，顺序正确 |
| 意图节非空 | 含用户原话的逐字片段 |
| 无思考段 | 不含 `<analysis>` |
| 无工具调用 | 正文里没有工具调用结构 |
| 长度合理 | 不长于被压缩的内容 |

任一项不通过就判失败，退回确定性摘要。

## 9. 防退化清单

每次改动 prompt 或工具描述时，逐条问：

| 问题 | 期望答案 |
|---|---|
| 这次的跨调用纪律进哪个节 | 静态轨 `tool_discipline` |
| 这次的 description 谁贡献 | 工具提供方 |
| 工具不在场时哪段消失 | 明确到具体条目 |
| 有没有和已有内容重复 | 删掉重复的那一处 |
| 数值是不是插值的 | 是 |
| 变量是不是静态的 | 是 |
| 体积有没有超预算 | 没有 |

## 10. 文档与实现同步

prompt 文本的变更要同步三处：

| 位置 | 内容 |
|---|---|
| 配置 | `prompt_sections` 的正文 |
| 文档 | 本文与 [02-system-prompt.md](02-system-prompt.md) 引用的模板 |
| 测试 | 断言涉及的哈希或内容 |

只改其中一处，模板与实现就会漂移。漂移之后，文档不再可信。
